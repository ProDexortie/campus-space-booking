# Campus Space Booking API

Сервис бронирования рабочих мест, переговорок и зон совместной работы в университетском коворкинге. Проект спроектирован по принципам чистой слоистой архитектуры (Clean/Layered Architecture) с разделением ответственности между API-контроллерами, сервисами бизнес-логики и слоем доступа к данным (Repository pattern).

В проект встроен минималистичный веб-интерфейс на нативном HTML5, CSS и JavaScript для удобного тестирования сценариев регистрации, просмотра пространств и бронирования слотов.

---

## Стек технологий

- **Язык & Рантайм:** Python 3.11+ / 3.13
- **Веб-фреймворк:** FastAPI (асинхронные эндпоинты, внедрение зависимостей через `Depends`)
- **Валидация и настройки:** Pydantic v2, `pydantic-settings`
- **База данных & ORM:** PostgreSQL, драйвер `asyncpg`, SQLAlchemy 2.0 (декларативный стиль `Mapped`, `mapped_column`)
- **Миграции БД:** Alembic (асинхронный `env.py`)
- **Кэширование:** Redis (асинхронный клиент `redis.asyncio` для каталога мест с инвалидацией при изменениях)
- **Фоновые задачи:** Celery + Redis (асинхронные подтверждения броней, периодический перевод прошедших броней в статус `EXPIRED`)
- **Безопасность:** JWT (Access + Refresh токены), хэширование паролей через `bcrypt`
- **Тестирование:** `pytest`, `pytest-asyncio`, `httpx` (AsyncClient) на изолированной асинхронной SQLite БД
- **Линтинг и типизация:** Ruff, Mypy
- **Контейнеризация:** Docker (multi-stage non-root образ), Docker Compose

## Бизнес-правила и особенности реализации

1. **Защита от овербукинга (Conflict Detection):**
   - При создании бронирования сервис проверяет отсутствие пересечений по формуле: `start_time < existing.end_time AND end_time > existing.start_time` для подтвержденных броней того же ресурса.
   - В PostgreSQL запрос сопровождается строкой блокировки `FOR UPDATE` для предотвращения race condition.
   - При пересечении интервалов возвращается кастомное исключение с HTTP-кодом `409 Conflict` и понятным описанием ошибки.

2. **Валидация длительности:**
   - Нельзя создавать бронирование «задним числом».
   - Минимальная длительность слота — 30 минут, максимальная — 8 часов.
   - Время окончания должно быть строго позже времени начала.

3. **Кэширование каталога пространств:**
   - Публичный список зон кэшируется в Redis с учетом переданных фильтров (вместимость, наличие проектора, маркерной доски).
   - При добавлении, изменении или удалении пространства администратором кэш автоматически инвалидируется по паттерну.

4. **Фоновые процессы Celery:**
   - При создании брони диспетчеризуется фоновая задача логирования/отправки подтверждения пользователю.
   - Периодическая задача `cleanup_expired_bookings` автоматически переводит завершенные бронирования в статус `EXPIRED`.

## Быстрый старт

### 1. Запуск через Docker Compose (рекомендуется)

Все сервисы (API, PostgreSQL, Redis, Celery Worker, Celery Beat) поднимаются одной командой:

```bash
docker compose up --build
```

После старта будут доступны:
- Веб-интерфейс: [http://localhost:8000/](http://localhost:8000/)
- Интерактивная документация Swagger: [http://localhost:8000/docs](http://localhost:8000/docs)
- Альтернативная документация ReDoc: [http://localhost:8000/redoc](http://localhost:8000/redoc)

---

### 2. Локальный запуск через виртуальное окружение

#### Шаг 1: Создание и активация виртуального окружения

```bash
# Linux / macOS
python3 -m venv venv
source venv/bin/activate

# Windows (PowerShell)
python -m venv venv
.\venv\Scripts\Activate.ps1
```

#### Шаг 2: Установка зависимостей

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

#### Шаг 3: Настройка переменных окружения

Скопируйте пример файла конфигурации:

```bash
cp .env.example .env
```

При необходимости отредактируйте параметры подключения к PostgreSQL и Redis. Для быстрого локального запуска без Postgres можно использовать SQLite:
`DATABASE_URL=sqlite+aiosqlite:///./local_dev.db`

#### Шаг 4: Применение миграций базы данных

```bash
alembic upgrade head
```

#### Шаг 5: Запуск веб-сервера

```bash
uvicorn src.main:app --reload --host 127.0.0.1 --port 8000
```

#### Шаг 6: Запуск Celery Worker (опционально)

```bash
# Linux / macOS
celery -A src.tasks.celery_app worker -l info

# Windows
celery -A src.tasks.celery_app worker -l info -P solo
```

## Тестирование и контроль качества кода

### Запуск автотестов (pytest)

Набор из 22 асинхронных интеграционных и модульных тестов покрывает аутентификацию, права доступа, CRUD пространств, создание бронирований, конфликты слотов, отмену и фоновые задачи Celery:

```bash
pytest -v
```

```bash
# Проверка стиля и потенциальных ошибок
ruff check .

# Проверка форматирования кода
ruff format --check .

# Строгая статическая проверка типов
mypy src
```
